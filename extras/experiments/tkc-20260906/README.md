## Commands used on this machine

Only run motion commands with an operator present and the camera path clear. The operator authorized ordinary `G28` and a minimum transit height of Z=40 before tool changes.

```gcode
G28
G90
G0 Z40 F600
M400
INITIALIZE_TOOLCHANGER
TKC_STATUS
CALIBRATION_NAVIGATE STATION=CAMERA
CALIBRATION_TEST_VISION SAMPLES=7
TKC_TEST_XY TOOLS=0,1,2,3,4
```

`TKC_TEST_XY` is the machine-owned wrapper. It forces `CALIBRATE_Z=0 SAVE_CONFIG=0 DRY_RUN=0 CLEAN_NOZZLE=0 SAMPLES=3 WIGGLE=0`, requires cold heater targets, and checks active/detected tool agreement. A hook lifts to machine Z=40 before tool changes. The native Z command hooks raise an error because the TKC Cartographer backend has not been validated in this session.

The bare upstream `CALIBRATE_TOOL_OFFSETS` defaults to **XYZ and SAVE_CONFIG=1**. Use the wrapper for this trial. `DRY_RUN=1` still changes tools and performs XY motion; it only skips Z probing and writes. It is not a stationary simulation.

The camera matrix is installation-specific. On this camera, a positive machine X or Y move makes the respective image coordinate decrease. The upstream uncalibrated fallback assumes the opposite direction and must not drive this printer. The first successful calibration was bootstrapped using measured +/-0.5 mm displacements; see `evidence/pilot.json` and `evidence/pilot-transform.json`. Do not reuse this matrix after moving, rotating, refocusing, or changing the resolution of the camera.

After a G-code error, KTC clears its active tool even if XYZ remains homed. Inspect the detected tool and physical state before `INITIALIZE_TOOLCHANGER`; do not bypass the wrapper's guard.

## Monitoring and maintenance

Use Moonraker directly at `http://192.168.1.43:7125` for long API G-code requests, or use its WebSocket API. The nginx port-80 endpoint returned HTTP 504 after 60 seconds while the original calibration continued. A request timeout is not cancellation; inspect the console and motion state before sending anything else.

```sh
systemctl --user status tool-calibrator-experiment.service
journalctl --user -u tool-calibrator-experiment.service
curl http://127.0.0.1:8090/health
```

To view the diagnostic UI from a PC, open an SSH tunnel in a terminal:

```sh
ssh -N -L 18090:127.0.0.1:8090 voron@192.168.1.43
```

Then open `http://127.0.0.1:18090`. The daemon has no public LAN listener. No Moonraker updater was added for this experimental checkout.

After changing Python sources or symlinks, restart the **Klipper service process**. A soft `RESTART` in the same process retained the old Python module from the previous TKC installation and produced an obsolete command-collision error.

## Reinstalling and disabling the experiment

Archive existing files before changing any of them. Copy this folder's config and learned station into `/home/voron/printer_data/tkc-experiment/`, install the supplied user service under `~/.config/systemd/user/`, restore the reviewed extras links, and add this line before SAVE_CONFIG in live `printer.cfg`:

```ini
[include /home/voron/printer_data/tkc-experiment/tool-calibrator.cfg]
```

Keep the service checkout pinned and inspect existing symlinks before creating them. The upstream installer was not used because it also changes system packages, services, and Moonraker updater configuration.

To disable the trial, first archive the current live files, remove only the experimental include from live `printer.cfg` (or restore the exact pre-trial file if there are no later edits), stop/disable the user service, and restart the Klipper service. Keep the files and source for recovery. See `evidence/deployment.json` for the remote backup path and the daily log for the local backup.

A normal All-Config production deployment will replace live `printer.cfg` with the production copy and therefore remove the experimental include. It does not stop the separate user service. Decide whether to disable the trial before a normal production update.
